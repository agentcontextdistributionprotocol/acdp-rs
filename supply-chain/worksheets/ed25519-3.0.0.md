## What the code does

- `Signature` (`src/lib.rs:310-319`): `#[repr(C)] { R: [u8; 32], s: [u8; 32] }`, a plain byte
  container that does **not** validate `R` or `s` (documented at `:302-309`; validation is the
  verifier's job). `from_bytes` splits at 32 (`:327-336`); `from_slice` / `TryFrom<&[u8]>`
  require exactly 64 bytes, else `Error::new()` (`:348-352`, `:430-436`); `to_bytes` /
  `to_vec` reassemble (`:368-381`). `Debug` / `Display` print hex (`:438-451`).
- Optional `serde` (`:453-473`) through `serdect` hex-or-binary helpers into a fixed
  64-byte buffer; optional `zeroize` (`:475-481`) clears both components.
- Optional `zerocopy` derives on `Signature` and `PublicKeyBytes` (`:310-315`,
  `src/pkcs8.rs:235-241`). Both are `repr(C)` / `repr(transparent)` over `u8` arrays with no
  padding, so `FromBytes` / `IntoBytes` are layout-sound. Not compiled in ACDP.
- `src/hex.rs`: `LowerHex` / `UpperHex`, and `FromStr` that checks length 128, rejects mixed
  case and non-hex bytes, then parses pairs with `u8::from_str_radix` (`:49-86`). Safe slice
  code throughout.
- `src/pkcs8.rs` (feature `pkcs8`, off): RFC 8410 `KeypairBytes` / `PublicKeyBytes`. Decoding
  checks the algorithm OID `1.3.101.112`, rejects parameters, and strips the inner `04 20`
  OCTET STRING header with a slice pattern (`:157-192`); public-key decoding does the same
  over SPKI (`:271-288`). `KeypairBytes::from_bytes` uses `split_at(32)` plus `try_into
  ().expect(..)` on halves that are always 32 bytes (`:91-101`).

**ACDP use.** Only the `Signature` type, through `ed25519_dalek::Signature::from_slice`
(`crates/acdp-crypto/src/verify.rs:38`): a 64-byte length check and a copy. Every
security-relevant check (canonical `s`, `R` decoding, strict verification) is in
`ed25519-dalek` / `curve25519-dalek`, audited separately.

## Observations (not vet concerns)

- **Hygiene (feature-gated, off in ACDP).** Without the `zeroize` feature, `KeypairBytes`'
  `Drop` is a no-op (`src/pkcs8.rs:122-127`); and in `to_pkcs8_der` the stack copy
  `private_key` is zeroized only on the success path, since the `?`s at `:140,145,148` return
  early (`:150-151`). ACDP never builds the `pkcs8` feature.
