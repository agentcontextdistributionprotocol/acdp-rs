## Behaviour (what was read)

- `KGenerator::new` (`src/lib.rs:73-81`): `bits2octets(h)` into a scratch buffer sliced
  `[..x.len()]` of `q.to_be_bytes()`; this panics (safe slice panic, not UB) if the secret
  is longer than the modulus encoding. ecdsa passes `d.to_repr()`, which has exactly that
  length (`ecdsa-0.17.0/src/hazmat.rs:112`), so it is not reachable from ACDP.
- `fill_next_k` (`:87-98`): loops DRBG output through `bits2int` until `0 < k < q`
  (constant-time comparison `ct_lt` + `is_zero`), then `int2octets`. The `debug_assert`
  on `k.len()` is debug-only.
- `bits2int` (`:146-172`): drops whole trailing bytes, then right-shifts; the
  `expect("overflow")` fires only for inputs over 512 MiB. `int2octets` (`:193-209`)
  writes limbs into `out.rchunks_mut(Limb::BYTES)` within `out[..rlen]`.
  `bits2octets` (`:236-248`): one conditional subtraction via `ct_assign`.
- `HmacDrbg` (`src/hmac_drbg.rs:11-80`): NIST SP 800-90A HMAC_DRBG over
  `hmac::SimpleHmac<D>`; the `expect("HMAC key should be valid")` (`:78`) is unreachable
  because `SimpleHmac::new_from_slice` always returns `Ok` (hmac worksheet).
- `Debug` impls are `finish_non_exhaustive()` and print no state.
